# Transmerge

영어·한국어가 줄 단위로 섞인 문서에서 한국어를 추출하고, 교정한 한국어를 원래 문서에 다시 병합하는 TypeScript 웹앱입니다. 서버 없이 브라우저에서 모든 문서 처리를 수행합니다. 입력 문서는 저장하거나 전송하지 않습니다.

## 실행

```sh
npm ci
npm run dev
```

화면에 표시되는 로컬 주소를 열면 됩니다. `npm test`로 병합 로직을 검사하고, `npm run build`로 타입 검사와 정적 빌드를 실행합니다. `npm run preview`로 빌드 결과를 확인할 수 있습니다.

## 사용법

상단 **사용 방법** 버튼으로 단계별 안내를 열 수 있습니다. 닫기 버튼, **확인했어요**, `Esc` 또는 안내 바깥을 클릭해 닫습니다.

1. **한국어 추출**: 왼쪽 원문을 붙여넣고 버튼을 누릅니다. 오른쪽 추출본을 복사하거나 **교정 · 병합으로 이어가기**를 누릅니다.
2. **교정본 병합**: 왼쪽에는 원문, 오른쪽에는 그 원문에서 추출한 한국어를 교정한 문서를 넣습니다. **추출본 가져오기**로 원문에서 작업본을 생성할 수도 있습니다.
3. **변경사항 병합**: 원문·병합 결과·교정본을 나란히 확인합니다. 수정·추가·삭제는 색과 기호로 표시되고, 줄 번호와 문장 내부 변경도 강조됩니다. 스크롤이 동기화되며 위/아래 버튼으로 변경 위치를 이동할 수 있습니다.
4. **전체 복사**: 영어와 교정한 한국어가 함께 있는 병합 결과를 복사합니다. 삭제한 줄의 비교 표시는 복사되지 않습니다. **편집**을 누르면 입력을 다시 수정할 수 있습니다.

`⌘ + Enter` 또는 `Ctrl + Enter`로 현재 작업을 실행합니다. **예제로 시작하기**는 현재 입력을 예제로 바꿉니다. 병합 탭의 예제에는 수정과 추가가 포함되어 있습니다.

## 비교 기준과 처리 규칙

- 세 가지 버전은 **영한 혼합 원문**, **원문에서 자동 추출한 한국어 기준본**, **교정한 한국어**입니다. 별도의 기준본 입력은 필요하지 않습니다. 교정본은 반드시 왼쪽 원문에서 추출한 문서에서 시작하세요.
- 한글 음절·자모가 포함된 줄을 한국어로 판단합니다. 한국어와 `API` 같은 영문 용어가 한 줄에 있어도 전체 줄을 유지합니다. 한 줄 안에서 영문 구절만 지우는 기능은 아닙니다.
- 태그, 코드 펜스, 구분선 등 독립적인 구조 줄도 유지합니다. 추출본의 연속된 빈 줄은 한 줄로 정리하고 앞뒤 빈 줄은 생략합니다. 영어 제목·숫자만 있는 줄 등 한글이 없는 내용 줄은 추출하지 않습니다.
- Myers 줄 비교로 변경 구간을 찾고, 변경 구간 안에서는 문장 유사도로 수정/삽입 위치를 정렬합니다. 한국어 줄을 원래 위치에 교체하며 선택되지 않은 영어 줄과 공백을 보존합니다. 줄 분할·합치기처럼 대응이 모호한 편집은 결과를 확인하세요. 영어 문장과 한국어 문장의 의미를 추론하는 AI 기능은 없습니다.
- 삽입은 대응하는 한국어 줄 앞 또는 마지막 대응 줄 뒤에 배치됩니다. 교정본에서 줄을 삭제해도 그 줄에 대응하는 영어는 유지됩니다. 빈 교정본으로 병합하면 추출 대상 줄을 모두 삭제합니다.
- 변경이 없는 병합은 원문을 그대로 반환합니다. 변경이 있으면 원문의 LF/CRLF/CR 형식을 사용하며, 마지막 줄바꿈 유무는 교정본을 따릅니다.
- 입력은 메모리에만 있으므로 새로고침하면 사라집니다. 외부 Google Fonts를 로드하지만 입력 내용은 전송하지 않습니다. 폰트가 로드되지 않아도 시스템 폰트로 사용할 수 있습니다.

## GitHub Pages

정적 산출물 `dist/`를 배포하는 `.github/workflows/deploy.yml`이 준비되어 있습니다.

1. 이 프로젝트를 GitHub 저장소의 `main` 브랜치로 푸시합니다.
2. 저장소 **Settings → Pages → Build and deployment → Source**를 **GitHub Actions**로 선택합니다.
3. `main`에 푸시하거나 **Actions → Deploy to GitHub Pages → Run workflow**를 실행합니다.

워크플로는 `npm ci`, 테스트, 타입 검사 및 빌드 후 GitHub Pages에 배포합니다. 기본 브랜치가 `main`이 아니면 워크플로의 `branches`를 변경하세요. Vite의 `base: './'`로 저장소 하위 경로와 사용자 사이트 모두에서 상대 자산 경로를 사용합니다. 참고: [Vite 정적 배포 가이드](https://vite.dev/guide/static-deploy.html), [상대 base 경로](https://vite.dev/guide/build#relative-base).

## 구조

- `src/merge.ts`: 추출, 기준본 매핑, 줄 비교, 병합 및 화면용 대응 행
- `src/main.ts`: 탭, 입력, 변경 비교, 동기화 스크롤, 복사
- `src/style.css`: 반응형 화면과 변경 강조
- `src/merge.test.ts`: 공백·줄바꿈·추가·삭제·중복·영어 보존 및 반복 편집 검증

Vite + TypeScript, `diff`(Myers 비교), Vitest를 사용합니다.

## 외부 라이브러리 고지

배포 산출물에 포함되는 `diff`와 Vite 런타임의 저작권·라이선스 고지는 [THIRD_PARTY_NOTICES.txt](public/THIRD_PARTY_NOTICES.txt)에 보존하며, 빌드 시 사이트 루트에도 복사됩니다. 예제와 테스트 문서는 직접 만든 더미 텍스트입니다.
